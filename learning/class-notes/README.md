# Class notes

These notes turn class discussions into a reusable product-management reference. They are organized by learning sequence rather than by assignment.

## How to read these notes

Each session separates:

- core concepts and frameworks taught in class;
- examples used to explain those concepts;
- practical ways to apply the learning;
- common mistakes and open verification points.

> **Source boundary:** These are condensed from learner-provided class notes. Classroom examples, company references, and numerical illustrations are recorded as teaching material and have not been independently verified. Project research must use its own dated sources and evidence.

## Reusable session format

Future notes should use this structure:

1. Session at a glance
2. Learning objectives
3. Core concepts
4. Frameworks and decision tools
5. Examples from class
6. Practical application
7. Common mistakes
8. Quick reference
9. Questions or claims to verify

## Evidence rule

Class notes explain concepts. They are not evidence for assignment claims. When an assignment depends on a market number, competitor capability, user behaviour, or company example, verify it separately and cite the dated source in that project.
